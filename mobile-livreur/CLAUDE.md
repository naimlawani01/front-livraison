# Sonaiyaa Mobile Livreur

Flutter application intended for drivers to receive ride proposals, use GPS navigation, and manage their account/wallet.

## Status
- iOS **✅ publié sur l'App Store** — Apple ID `6765755989` → `https://apps.apple.com/app/id6765755989`. Bundle id `com.livraison.livreur`, display name `Sönaiyaa Livreur`.
- Android: not yet on Google Play (Play Console setup pending; Android keystore not yet created).
- App icon and adaptive icon use the Sonaiyaa cart logo (variant 2) generated by `flutter_launcher_icons` from `assets/branding/app_icon_1024.png` (cart fills 65% of the canvas — leaves visible breathing room around the logo on iOS/Android home screens).
- Native splash uses `assets/branding/logo_mark_splash.png` (cart fills 50% of a 1024×1024 transparent canvas, generated by `flutter_native_splash`).
- **First-launch onboarding**: 3 slides (welcome livreur / receive nearby rides / wallet & payouts) shown via `OnboardingScreen` (from `mobile_core`) before the login flow. Persisted via `OnboardingStorage.markSeen()`. Decision logic in `_AuthWrapperState` in `lib/main.dart`.
- **Boot-time hooks** (in `lib/main.dart`): `ErrorWidget.builder = AppErrorScreen.builder`, `AppVersion.warmup()`, non-blocking `ApiService.healthCheck()` (logs to Crashlytics if backend is down), `AnalyticsService.instance.navigatorObserver` registered on `MaterialApp` for automatic screen tracking.
- **Analytics events emitted**: `login` (role=livreur), `course_acceptee`, `livreur_online` / `livreur_offline` on availability toggle, `retrait_demande` (with `montant_gnf`, `methode`), `onboarding_completed`. Add new events in `mobile_core/lib/services/analytics_service.dart` to keep them consistent with the Partenaire app.
- **Home greeting**: shows `UserAvatar` (from mobile_core) using `livreur.photoProfilUrl` with initials fallback when no photo. Tapping the avatar navigates to the Profile tab (index 4) — the livreur can update the photo via `documents_screen.dart` (type `photo_profil`, uploaded to R2 via `POST /api/v1/livreurs/upload-document`).
- **Course active screen** (`screens/courses/course_active_screen.dart`): embeds a 220px Google Map at the top with two markers — orange = livreur live position (from `LocationProvider`), red = destination (commerce in step 0, client in steps 1-2). The "Itinéraire" CTA on the map opens Google Maps / Apple Maps for turn-by-turn navigation via `_navigate()`. Map is hidden when the course is in TERMINEE state.
- **Standalone `MapScreen`** (`screens/map/map_screen.dart`): legacy screen kept in the codebase but **not wired up to any route**. Real map UX lives inside `course_active_screen.dart`.
- Login screen displays `assets/branding/logo_mark_tight.png`.
- After modifying any branding asset, regenerate native icons: `dart run flutter_launcher_icons` and `dart run flutter_native_splash:create`, then `flutter clean && flutter pub get` before re-archiving in Xcode.

## Tech Stack
- **Framework**: Flutter / Dart
- **Shared Package**: Depends on `mobile_core/` for data models and API calls.
- **Real-Time**: Uses the `web_socket_channel` package via `WebSocketService` for instant reception of new orders.
- **Background GPS**: `flutter_foreground_task` — keeps GPS tracking alive as a foreground service (shows a persistent notification).
- **Push Notifications**: `flutter_local_notifications` — displays FCM push notifications.
- **Document Upload**: `image_picker` — lets drivers upload ID, vehicle docs, and profile photo to Cloudflare R2 via the backend.
- **Splash Screen**: `flutter_native_splash`

## Common Commands
- **Run the app**: `flutter run`
- **Update dependencies**: `flutter pub get`

## Specific Rules & Architecture
- **WebSockets & Security**: `WebSocketService` authentifie via le **sous-protocole WS** — `WebSocketChannel.connect(uri, protocols: ['bearer', token])` — pour garder le JWT **hors de l'URL** (sinon il fuit dans les logs serveur/proxy). Le backend accepte encore `?token=` en repli legacy, mais les nouvelles versions doivent utiliser le sous-protocole. Sans token valide (`type == "access"`, `sub` == userId), la connexion est refusée.
- **Driver State**: Business logic dictates that a driver only receives rides IF they are switched to the "Online" status. ⚠️ **Nouveau modèle** : plus de blocage lié au solde (l'ancienne règle « balance > -5000 GNF » est **abandonnée**). Le livreur n'avance plus rien — les courses cash sont réglées en direct par l'expéditeur, et le garde-fou (Crédit insuffisant) est désormais côté expéditeur, à la création de course.
- **Écran Gains** (`screens/wallet/wallet_screen.dart`, onglet « Gains ») : ex-« Wallet », re-skiné selon l'identité validée (carte claire, chiffres mono `AppTheme.mono`, motif deux-points, orange sobre). **Solde positif uniquement** (courses Mobile Money + indemnités) ; bouton **Retirer** seul (plus de « Recharger » — endpoint backend supprimé) ; plus de dette/commission côté livreur.
- **API Pagination**: List endpoints like `/mes-courses` return a paginated format (`{"commandes": [...]}`). Ensure the UI correctly extracts this list.
- **Document Upload Flow**: Use `image_picker` to pick a file, then POST it to `POST /api/v1/livreurs/upload-document` with the document type (`piece_identite`, `vehicule_doc`, `photo_profil`). The backend stores it in Cloudflare R2 and returns the URL.
- **Foreground Task**: The GPS foreground service must be properly started/stopped when the driver toggles Online/Offline to avoid battery drain and OS kills.
- **Redesign premium (fait)** : app alignée sur l'identité premium partagée (`AppTheme` : **Manrope**, fond blanc chaud, nav bar orange, ombres douces). Écrans traités : **Accueil** (card **Gains** en hero orange dégradé + glow, libellé « Mes gains », accents corrigés), **Profil** (avatar dégradé + glow, badge **Vérifié**, ombres douces), **Course active** (carte d'étape + boutons action/itinéraire en **dégradé orange**), **Disponibles** (refresh/spinner accent), **Mes courses** (carte course active en dégradé orange, fait écho au hero). Langage cohérent : orange = actif/primaire (le noir a été retiré des éléments primaires). Tous les `withOpacity` dépréciés remplacés par `withValues`.
- **Aperçu web** : `flutter run -d chrome --web-port=5173`. `main.dart` garde `FlutterNativeSplash`, `ForegroundLocationService`, `WithForegroundTask` et `NotificationService` derrière `kIsWeb` (ils ne fonctionnent pas sur Chrome). La carte Google Maps s'affiche vide sur web sans clé, mais l'app ne crashe pas.
