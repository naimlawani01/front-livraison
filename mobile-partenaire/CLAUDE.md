# Sonaiyaa Mobile Partenaire

Flutter application intended for businesses (restaurants, pharmacies, shops) to create and track their customers' orders.

## Status
- iOS **✅ publié sur l'App Store** — Apple ID `6765756215` → `https://apps.apple.com/app/id6765756215`. Bundle id `com.livraison.partenaire`, display name `Sönaiyaa Partenaire`.
- Android: not yet on Google Play (Play Console setup pending; Android keystore not yet created).
- App icon and adaptive icon use the Sonaiyaa cart logo (variant 2) generated by `flutter_launcher_icons` from `assets/branding/app_icon_1024.png` (cart fills 65% of the canvas — leaves visible breathing room around the logo on iOS/Android home screens).
- Native splash uses `assets/branding/logo_mark_splash.png` (cart fills 50% of a 1024×1024 transparent canvas, generated by `flutter_native_splash`).
- **First-launch onboarding**: 3 slides (welcome / create order / track real-time) shown via `OnboardingScreen` (from `mobile_core`) before the login flow. Persisted via `OnboardingStorage.markSeen()`. Decision logic in `_AuthWrapperState` in `lib/main.dart`.
- **Boot-time hooks** (in `lib/main.dart`): `ErrorWidget.builder = AppErrorScreen.builder`, `AppVersion.warmup()`, non-blocking `ApiService.healthCheck()` (logs to Crashlytics if backend is down), `AnalyticsService.instance.navigatorObserver` registered on `MaterialApp` for automatic screen tracking.
- **Analytics events emitted**: `login` (role=partenaire), `commande_creee` (with `prix_gnf`), `onboarding_completed`. Add new events in `mobile_core/lib/services/analytics_service.dart` to keep them consistent with the Livreur app.
- **Login error UX**: `login_screen.dart` exposes a `_globalError` state that renders an inline red error block above the inputs whenever authentication fails (wrong credentials, server unreachable, etc.). This was added after Apple build 12 was rejected for not surfacing login errors — `Overlay.of(context)` (used by `UIUtils.showError`) is not 100% reliable in all layout contexts (notably iPad compat mode). Keep BOTH the inline block AND the toast — the inline block is the guaranteed-visible signal, the toast is the polished cherry on top.
- **AuthProvider has TWO loading flags**: `isInitializing` (only true during boot `init()` while we check the saved token) and `isLoading` (true during a live login/register call). The `AuthWrapper` in `main.dart` must only branch on `isInitializing` for the blank-scaffold gate. Branching on `isLoading` would unmount `LoginScreen` mid-login, wiping the inline `_globalError` state.
- Login screen displays `assets/branding/logo_mark_tight.png`.
- After modifying any branding asset, regenerate native icons: `dart run flutter_launcher_icons` and `dart run flutter_native_splash:create`, then `flutter clean && flutter pub get` before re-archiving in Xcode.

## Specific Rules
- **API Integration**: Do not code raw HTTP logic here. Systematically use the `ApiService` coming from the local `mobile_core` package.
- **Response Format**: Endpoints returning lists (e.g., order history) now return paginated objects (`{"commandes": [...]}`). Ensure the UI correctly parses the `commandes` key.
- **Payment Flow**: Order creation can trigger a GeniusPay Mobile Money checkout. The checkout URL is returned by the backend (`geniuspay_checkout_url`) and should be opened in a WebView or external browser.
- **Crédit (nouveau modèle)** : l'expéditeur (le mot « partenaire » côté code = **Expéditeur** côté produit) dispose d'un **Crédit prépayé** qui couvre les commissions plateforme (12 %). Écran dédié `screens/credit/credit_screen.dart` (onglet **« Crédit »**, index 2 — Profil est passé à l'index 3), piloté par `providers/credit_provider.dart` (`getCredit` / `getCreditTransactions` / `rechargeCredit`). Identité validée : carte claire, chiffres mono (`AppTheme.mono`), motif deux-points, orange sobre sur **Recharger** (ouvre un checkout Mobile Money via `url_launcher` ; le Crédit est crédité après confirmation du webhook). La **commission d'une course cash est débitée du Crédit à la création** — si le Crédit est insuffisant, la création est refusée (400).
- **Qui paie la course (backend `payeur`)** : à la création, l'expéditeur choisit « Moi » ou « Mon client » (`payeur` = `expediteur` | `client`). Client ⇒ **Mobile Money obligatoire** (le cash est désactivé). Répartition affichée : livreur 88 % / commission 12 %. Expéditeur + cash → il remet la part livreur en espèces à la récupération ; expéditeur + MM → bouton **Payer** dans le détail (`geniuspay_checkout_url` ou `ApiService.relancerPaiement`) ; client → la commission lui est rendue dès que le client a payé.
- **Code de livraison activé par défaut** (envoyé au client par SMS par le backend).
- **Détail de course** : bouton **Relancer la course** (`ApiService.rediffuserCourse`) pour une course cash restée `CREEE` après le partage GPS (Crédit insuffisant) ; info **remboursement dû** au client ; **annulation masquée en `EN_LIVRAISON`** (colis en main → support) ; avertissement d'**indemnité 3 000 GNF** si un livreur est déjà en route.
- **Document Upload**: Merchants can upload a storefront photo (`devanture_url`) via `POST /api/v1/partenaires/me/upload-document`. Uses `image_picker` (same version as mobile-livreur).
- **Design System**: Use the Sonaiyaa brand colors (Accent Orange `#FF5A1F`). Keep the "Pro Delivery" interface clean and intuitive, adapted for busy merchants.
- **Design (skill `sonaiyaa-design`, fait)** : onglets Accueil · Courses · Crédit · Profil ; composants communs de `mobile_core` (`PrimaryCta`, `SecondaryButton`, `CourseFrise`, 4 états, `AppSheet`/`showConfirmAction`).
  - **Accueil** : Crédit en chiffre héros (alerte si trop bas), courses en cours avec frise (`widgets/course_card.dart`, partagé avec la liste), « Nouvelle course » en bouton du bas (grisé tant que le compte n'est pas vérifié). Chargement une seule fois à l'ouverture (avant : à chaque reconstruction).
  - **Nouvelle course** (< 30 s) : client → qui paie → colis → précisions repliées → code de livraison → « Ce que ça coûte » ; prix + bouton collés en bas. Le prix reste provisoire (10 000 GNF) jusqu'au partage GPS du client : l'estimation n'est jamais disponible à la création.
  - **Détail** : statut + frise, livreur, carte, paiement (répartition 88/12), client, historique horodaté ; « Payer » / « Relancer la course » en bouton du bas ; annulation en feuille.
  - **Crédit** : solde en héros, mouvements par jour (types `recharge`, `commission`, `remboursement`, `avoir`, `indemnite`, `ajustement_admin`), feuille de recharge.
  - Compte : Connexion, Inscription (activité en puces, position GPS du commerce), Profil, Modifier le profil (adresse verrouillée si compte vérifié — le backend la refuse, cf. anti-fraude prix), Documents.
- **Aperçu web** : `flutter run -d chrome --web-port=5173` (les hooks natifs sont déjà gardés par `kIsWeb` dans `main.dart`).
- **Livraison impossible / retour du colis** : course en `RETOUR` → détail avec « J'ai récupéré le colis » en bouton principal (`POST /courses/{id}/retour-recu`, confirmation qui annonce les frais de retour = 50 % du prix, pris sur le Crédit). Frais de retour impayés (`frais_retour_dus` de `GET /expediteurs/me/credit`, `CreditProvider.fraisRetourDus`) → alerte sur l'Accueil et le Crédit, « Nouvelle course » bloqué jusqu'à la recharge (le backend refuse la création). Course finie = `Course.isFinie` (TERMINEE, ANNULEE, RETOURNEE).
